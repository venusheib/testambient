# Batch Modify (modifyBatch)

Modify multiple orders in a single transaction using the Ambient Ember SDK for proper signing.

## Request Schema

### Headers

| Field | Type | Description |
|-------|------|-------------|
| Content-Type* | String | "application/json" |

### Body

| Field | Type | Description |
|-------|------|-------------|
| action* | Object | { "type": "modifyBatch", "modifies": [{ "oid": Number \| String, "order": { "a": Number, "b": Boolean, "p": String, "s": String, "r": Boolean, "t": { "limit": { "tif": "Alo" \| "Ioc" \| "Gtc" } or "trigger": { "isMarket": Boolean, "triggerPx": String, "tpsl": "tp" \| "sl" } }, "c": Cloid (optional) } }] } |
| nonce* | Number | Recommended to use the current timestamp in milliseconds |
| signature* | Array | Hex signature array - one signature per modification (can be generated by the SDK here: https://github.com/CrocSwap/ambient-ember-sdk/blob/main/scripts/signPayload.mjs) |
| pubkey* | String | Solana pubkey of signer and wallet of user |
| permitBytes | String | Optional. Byte string encoding of action payload. |

**Field Meanings:**
- oid is original order ID to modify
- a is asset
- b is isBuy  
- p is price
- s is size
- r is reduceOnly
- t is type
- c is cloid (client order id)

## Response Schema

| Field | Type | Description |
|-------|------|-------------|
| status | string | Overall status: "ok" or "err" |
| response | Array | Array of modification results (one per order) |
| response[].status | string \| Object | Individual transaction status: "ok" or error object |
| response[].data.type | string | Operation type: "modify" |
| response[].data.oid | string | New order ID assigned by exchange (original order is canceled) |
| response[].data.cloid | string | Client order ID (new or provided) |
| response[].data.filled.totalSz | string | Total filled size |
| response[].data.filled.avgPx | string | Average fill price |
| response[].tx | string | Transaction hash on blockchain for this modification |

## Key Features

- **Order Replacement**: Original orders are canceled and new orders created with new IDs
- **Atomic Batch Processing**: All modifications processed in single transaction
- **Individual Results**: Each modification gets its own result object and transaction hash
- **Multi-Signature Support**: SDK generates separate signatures for each modification
- **Partial Success Handling**: Some modifications can succeed while others fail
- **Client Order ID Support**: Custom CLOIDs supported per modified order
- **Price/Size Updates**: Full order parameter modification (price, size, TIF, etc.)

## Important Notes

- **Action Type**: Use `"modifyBatch"` (not `"batchModify"`)
- **Order ID Changes**: Modified orders receive new order IDs
- **Original Orders Canceled**: Modification process cancels original orders first
- **Blockchain Errors**: Transaction simulation failures are normal for invalid order states
- **Signature Requirement**: Each modification requires its own cryptographic signature
